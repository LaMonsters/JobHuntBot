> 2026-09-07 分享版已同步。完整启动与备份步骤见根目录 [使用说明.txt](../使用说明.txt)。首次使用为 0 条记录，不自动生成示例；已有浏览器记录继续保留。

## 打开

直接双击本目录的 **dashboard.html**，在 Edge、Chrome 或 Firefox 中打开即可。无需安装依赖，无需联网，无需启动服务器。

也可使用 `start-dashboard.bat` / `start-dashboard.sh`，从 `http://localhost:8420/dashboard.html` 打开。Windows 的启动脚本现在会将服务放到后台，无需保留命令窗口；重复运行会复用已启动的服务。两种打开方式的数据存储空间不同，请固定使用一种方式，需要切换时先导出，再导入备份。

## Windows 自动启动

如需登录 Windows 后自动在后台启动 OfferTrack，请运行根目录的“设置登录后自动启动.bat”。设置后登录本机，在浏览器打开 `http://localhost:8420/dashboard.html` 即可；关闭浏览器后，后台服务仍会运行。下载源码本身不会自动设置开机启动。

自动启动入口位于当前用户的 Windows“启动”文件夹，名称为 `OfferTrack.lnk`。如需取消，按 `Win + R`，输入 `shell:startup`，删除这个快捷方式即可；已运行的后台服务会在注销或关机时退出。删除快捷方式不会删除岗位记录。

移动项目文件夹或更改 Node.js 安装路径后，需要在新位置重新运行 `install-autostart.ps1` 更新入口。服务意外停止时，双击 `start-dashboard.bat` 可重新启动。该自动启动适用于当前 Windows 账户，本地服务只监听本机地址。

运行日志保存在 `%LOCALAPPDATA%\OfferTrack`，启动错误可查看 `launcher-error.log` 或 `server-error.log`。

## 岗位信息库

侧边栏的「岗位信息库」内嵌你提供的飞书校招表格，直接保留原表格和视图。可在表格中搜索、筛选和切换视图，也可点击「在飞书打开」进入原表格；「重新加载」会重新连接表格。

入口：[岗位信息库](http://localhost:8420/dashboard.html#job-library)。仅在首次进入该模块时加载飞书，切换到其他模块再回来会保留表格当前状态。找到合适的岗位后，点击「添加岗位」在原表单中记录投递。

表格需要联网，访问权限和登录状态由飞书管理；如内嵌区域未显示，先在飞书页面登录或确认访问权限，再返回重新加载。这里展示在线表格，不会自动导入到「我的投递」，原岗位记录和简历仍按原方式保存。

本轮在当前最新完整版本 `596703f` 上追加此模块，该提交也是修改前恢复点；未切换到较早的 `6a17bc6` 版本。

## 功能

- 侧边栏的五个入口是「总览」「我的投递」「添加岗位」「简历管理」「投递复盘」，共同使用原工作台的数据。
- 总览增加岗位总量、本周投递趋势、三天内截止、今日待办、行动建议和可切换月份的投递台历。点击待办或台历中的记录可编辑对应岗位。
- 我的投递支持阶段卡片和表格切换。卡片可拖到新的阶段，也可用卡片底部的下拉框更新；未填写投递日期时，第一次移入已投递等阶段会填入当天日期。看板列名可自定义，原阶段含义保留。
- 收藏、标签和手动匹配度在岗位的补充信息中记录；支持相应快捷筛选。高匹配度指手动记录至少 80 分；「未设置时间」指未填写截止、笔面安排和跟进日期。
- 投递复盘可切换周次，查看该周投递量和笔面安排、累计推进率、当前阶段分布、停滞岗位及后续行动。在岗位的「投递进度与安排」中填写个人复盘，保存后会集中展示。
- 「导出投递记录」导出当前筛选结果的 CSV，适合 Excel 查看；「导出备份」导出全部记录的 JSON，包含复盘、收藏和阶段历史，适合恢复。
- 顶部统计：投递总数、进行中的流程、七天内的安排、Offer 数量。
- 新增、编辑和删除投递；删除前确认，删除后 10 秒内可撤销。
- 岗位信息依次为：公司名称、岗位名称、城市、岗位类型、投递链接、截止日期、岗位描述 JD、备注、绑定简历版本。
- 岗位类型为产品岗、技术岗、数据岗等分类下拉框；旧记录中的原类型会继续保留。截止日期留空表示招满为止。
- 侧边栏「简历管理」支持批量选择或拖拽上传多份 PDF、查看、下载、重命名和删除。上传后的文件可以在岗位表单「绑定简历版本」中选择，并从岗位列表直接打开。
- 点击“添加版本名称”仍可记录仅有名称的旧版本；已有名称和旧备份继续兼容。
- 招聘专业、学历、薪资收在“补充岗位信息”；投递日期、阶段、最近安排及时间、下一步行动收在“投递进度与安排”，展开即可编辑。
- 按状态、具体阶段、城市及关键词筛选，默认按投递日期从新到旧排列。
- 一周安排按时间排序，点击日期筛选当天，再点一次恢复整周。
- JSON 备份导出、校验和恢复；导入替换前确认。
- 首次打开为 0 条记录，不生成虚构示例；已有浏览器中的记录继续保留。
- 手机和窄屏布局；表格可横向滚动。

## 从岗位页面自动录入

项目中的 `../offertrack-extension` 是 Edge / Chrome 岗位采集插件，安装步骤见该文件夹中的 `使用说明.md`。

打开单个招聘岗位 → 点击插件 → 核对公司、岗位、城市、岗位类型、投递链接、截止日期与 JD，按需填写备注和简历版本名称 → 点击“填入工作台的岗位信息” → 核对并点击“保存岗位”。工作台与插件的字段、顺序一致，招聘专业、学历、薪资仍随岗位保留。

新增及刚采集的岗位默认“待投递”，不计入顶部投递总数和进行中的流程。实际网申完成后展开“投递进度与安排”，切换为“已投递”，并确认投递日期。招聘截止日期与面试安排分别记录，下一步行动按实际情况填写。列表可以按“待投递”筛选，搜索支持 JD、招聘专业、岗位类型、备注及简历版本名称。

页面上的“导入岗位”、岗位表单右上角的“从插件导入”均可读取插件下载的单个岗位 JSON，只填入一条待确认的表单，不会覆盖整个列表。重复链接或同公司/岗位/城市会提示检查已有记录。原有的“导入备份”仍是恢复全部记录。

本次按参考图调整表单，未接入 AI 解析或简历匹配服务。已有记录、旧岗位采集文件和旧版备份保持兼容。

## 保存位置

简历 PDF 与索引保存在本工作台的 `dashboard/.resume-data/` 文件夹，不依赖浏览器缓存。单份最大 20 MB，不设置份数上限；同名不同内容分别保存，内容完全相同的文件提示重复并跳过。删除只影响工作台中的副本，最初上传的原文件不受影响。删除或重命名简历不会改写已保存岗位中的历史版本名称。

简历管理集成在原入口 `http://localhost:8420/dashboard.html` 的侧边栏内，也可通过 `http://localhost:8420/dashboard.html#resumes` 直接进入。原 Windows 自动启动方式继续使用。直接双击 HTML 的文件模式仍可管理岗位；上传简历请用上面的本地网址。

岗位 JSON 备份包含简历版本名称和绑定编号，不包含 PDF 文件。备份或迁移简历时，在没有文件上传、重命名、删除操作时复制整个 `.resume-data` 文件夹；恢复文件夹后，原岗位绑定编号可继续使用。该文件夹已经加入 Git 忽略规则。

基础版数据保存在当前浏览器的 localStorage，键名为 `jobhuntbot.offertrack.v1`，不会上传到网络。浏览器限制存储或写入失败时会明确提示，避免把未保存修改显示为成功。

请保持浏览器、文件路径、访问地址一致。隐私窗口、清理浏览器数据、换浏览器、移动网页或切换 `file://` 与 `http://localhost` 可能使原数据不可见。建议定期点击“导出备份”保存 JSON 文件。

导入备份会替换现有记录，包括导入空备份。导入前可先导出当前数据。最多 5 MB、5000 条记录。无效数据不会覆盖现有数据。

## 统计口径

- 投递总数：除“待投递”外的记录，包括已经结束的流程。
- 进行中：已投递、筛选中、笔试、一面、二面、HR 面；不含 Offer、已结束、已撤回。
- 七天内安排：按本机日期，从今天 00:00 到第七天 23:59，即今天及未来六天。包含今天已过的时间并在记录中标记；排除已结束和已撤回。每条投递保存一项最近安排。
- Offer：当前阶段为“已获 Offer”的记录。
- 本周投递：本机时间周一至周日，按岗位中保存的投递日期统计，排除待投递。
- 三天内截止：今天及后两天截止的待投递岗位。已过期的待投递岗位会出现在今日待办中。
- 今日待办：截止到期的待投递岗位、今天的笔面安排、已到期的跟进；一个岗位可能有多项待办。完成后可更新阶段、清空已完成安排或设置新的跟进日期。
- 累计推进率：当前或历史进入过笔试、面试或 Offer 的已投递岗位数 ÷ 已投递岗位总数；已结束的岗位若有推进历史，仍计入。旧记录缺少历史时仅依据已知的当前阶段，不猜测过去进展。
- 长时间没进展：进行中的岗位至少 14 天未发生阶段变化；没有阶段历史的旧岗位使用投递日期。复盘的近期处理列表始终针对当前日期，周切换只改变周统计与趋势。
- 每个岗位保存一项最近安排；改写安排后，周统计使用改写后的时间。台历中的结果日期来自保存的阶段变更记录。

## 与原有 JobHuntBot 的关系

保留零依赖 HTML + Node 的项目结构，并更新原 `dashboard.html` 入口。新界面参照 Offerbiu 的浅蓝背景、蓝白卡片、侧边导航与亮蓝按钮设计，全部图标为本地内联 SVG，不依赖在线字体或 CDN。

原界面完整保存在 **dashboard-legacy.html**。原 `job_pool.csv`、`application_log.csv`、`follow_up.csv` 等文件及服务端接口均保留。本基础版使用浏览器存储，与 CSV **不自动同步**。旧版需要先运行原启动脚本，再访问 `http://localhost:8420/dashboard-legacy.html`。

`autumn.css` 为新样式，`autumn.js` 为记录管理与持久化逻辑，`favicon.svg` 为本地图标。

`resume-library.js` / `resume-library.css` 为集成的简历管理界面，`resume-api.js` 为原 Node 服务中的本地文件接口。无需启动另一个服务，也不包含简历优化功能。

`workspace.js` / `workspace.css` 为原工作台的总览、卡片看板、日历和复盘扩展，`workspace-data.js` 为共享统计计算。五项功能的验收说明见 `qa/五项功能验收.md`，可重跑 `node dashboard/qa/verify-workspace.cjs` 与 `node dashboard/qa/verify-resume-integration.cjs`（在项目根目录，需本机 Edge 和 Playwright）。测试使用隔离浏览器和临时简历目录。
