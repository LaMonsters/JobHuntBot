# OfferTrack 岗位采集助手

在招聘岗位详情页点插件，读取岗位信息；预览与工作台按同一顺序显示：公司名称、岗位名称、城市、岗位类型、投递链接、截止日期、岗位描述 JD、备注、绑定简历版本。核对后点击“填入工作台的岗位信息”，在工作台点击“保存岗位”后才进入列表。

## 安装到 Edge（只需一次）

1. 在地址栏输入 `edge://extensions`。
2. 打开“开发人员模式”，点击“加载解压缩的扩展”或“加载已解压的扩展程序”。
3. 选择本文件所在的 `offertrack-extension` 文件夹，里面应有 `manifest.json`。
4. 在浏览器扩展菜单中，把 **OfferTrack 岗位采集助手** 固定到工具栏。

Chrome 在 `chrome://extensions` 中打开“开发者模式”，选择“加载已解压的扩展程序”，其余步骤相同。修改插件文件后，在扩展管理页点击该插件的“重新加载”。不需要 GitHub 登录，也不需要账号或 API Key。

## 日常使用

1. 使用原来的方式打开工作台。Windows 设置自动启动后，直接访问 `http://localhost:8420/dashboard.html` 即可；服务未启动时双击 `dashboard/start-dashboard.bat`，服务会在后台运行，无需保留命令窗口。
2. 在企业官网或招聘网站打开**单个岗位的详情页**，展开完整的职位描述，等内容加载完成。
3. 点击工具栏的 OfferTrack 插件，它会自动读取当前页面。
4. 检查公司、岗位、城市、岗位类型、投递链接、截止日期和 JD，按需添加备注及简历版本名称。再点“填入工作台的岗位信息”。插件会优先复用已经打开的同地址工作台，并切换过去；只有没打开时才新建标签页。其他浏览器窗口中的工作台也可复用。已有未保存的表单时，工作台会先询问是否替换。
5. 在工作台核对并保存。已经投递的岗位，修改阶段为“已投递”并确认真实投递日期；刚收藏的岗位保留“待投递”。

工作台会提示同链接或同公司/岗位/城市的已有记录。可以编辑已有记录，或明确勾选后另存一条。旧数据和原有 JSON 备份继续可用。

## 岗位字段说明

- 岗位类型是产品岗、技术岗、数据岗、研发岗等职能分类，和“全职 / 实习 / 校招”不同。优先使用页面注明的类别；能从岗位名称归类时会给出提示，请核对下拉选项。不明确时留空。
- 投递链接默认当前岗位页地址；截止日期未注明时留空，工作台按“招满为止”记录。
- JD 保留完整的岗位职责和任职要求；“补充岗位信息”中仍保留招聘专业、学历和薪资。
- 备注读取页面明确标注的“岗位备注 / 招聘备注 / 备注”，也可以自行记录内推人或关注点。
- 简历版本默认留空，由你选择或添加版本名称，例如“数据分析简历 V2”。导入或下载后，插件会记住已用名称。这里只记录名称，不上传简历文件，不会从招聘网页猜测你的简历版本。工作台保存过的版本也可在工作台直接选择；两个下拉框不在后台同步。
- 这版是本地规则识别，没有接入 AI 解析 JD 或简历匹配服务。

## 使用本地 HTML 文件

如果平时双击 `dashboard.html`，把浏览器地址栏中的完整 `file:///…/dashboard.html` 地址复制到插件底部的“工作台地址”，然后保存。不要在 localhost 与 file 两种地址之间来回切换，因为各自的记录存储不同。

直接打开本地文件受浏览器策略影响时，用插件的“下载岗位文件”，在工作台选择“导入岗位”并选取文件。这是单个岗位导入，与会替换全部数据的“导入备份”分开。

## 识别不完整时

- 优先识别网页的 JobPosting 结构化信息，其次读取页面文字和常见职位详情元素。中文标签包括公司、工作地点、招聘专业、岗位职责、任职要求和截止日期。
- 页面布局差别很大，通用规则不能保证所有招聘网站都能准确识别。识别不到时会留空并提示，不会编造。
- 在页面上选中目标岗位的介绍文字，重新打开插件，再点击“读取选中文字”，可避免侧边推荐岗位混入 JD。
- 如岗位位于跨域内嵌页面，可把岗位所在页面单独打开后采集。浏览器设置页、扩展商店、图片和 PDF 不在本版识别范围。
- 投递日期、当前阶段、面试安排、下一步行动并非岗位介绍页面中的个人流程事实，因此不会从发布日期或报名截止日推断。初次导入默认“待投递”，这些个人进展由你确认。
- 插件保留最近一次采集，工作台暂时打不开时可“恢复上次采集”或下载岗位文件。关闭插件会保留上次成功读取/导入/下载时的内容；预览中未导入或下载的临时修改可能丢失。

## 数据与权限

本版只在点击插件时读取当前网页，使用 `activeTab`、`scripting`、`storage` 和 `tabs` 权限。`tabs` 用于按地址查找已打开的工作台，不保存其他标签页地址。不申请所有网站常驻内容权限，不读简历、不填写招聘申请、不提交网申。没有远程分析服务；最近采集存在扩展本地存储，记录存在工作台的浏览器 localStorage。向工作台传入的信息放在 URL 的 fragment 部分，不作为 HTTP 请求内容发送；工作台接收后会清理地址栏的岗位内容。

1.1.0 同步了新版岗位表单、岗位分类、备注和简历版本名称，保留 1.0.1 的标签页复用功能。更新后先在工作台按 `Ctrl + Shift + R` 刷新，再在扩展管理页点击该插件的“重新加载”。如果原来加载的是其他位置解压的副本，需要先用新版文件替换那份副本。地址以插件中配置的工作台地址为准，localhost、127.0.0.1 和 file 的数据空间不同，不会混用。
